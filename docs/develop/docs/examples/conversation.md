# 对话式需求示例

> 展示真实用法：模板原样发过去，需求在对话里用自然语言说，AI 先复述需求再开发。
> 下面以 C++ 模板为例，Python 模板的流程完全相同。

## 第 1 轮：用户发送模板

```text
（把 docs/cpp/template.md 的全部内容原样粘贴，不做任何修改。）
```

AI 的处理：对话里还没有需求，只回复引导，不写代码、不要求填表。

```text
已收到模板。请用自然语言说明：软件名称、核心功能、必须的系统能力、交付形态，
以及明确不做或需要特殊处理的部分。可以分多条说。
```

## 第 2 轮：用户用自然语言描述需求

```text
做个 Windows 上的进程端口查看器，叫 ProcessPortViewer。
能看到所有进程和监听端口，能按端口、PID、进程名搜索。
点击端口能跳到对应进程，右键复制 PID 和路径。
要能结束进程；没权限的时候给提示。
做成绿色版，不需要联网，不要开机自启。
不要托盘，关闭窗口就直接退出。
```

AI 的处理：先输出需求理解摘要，把自然语言映射到 `V1` / `V2`。

```text
需求理解（有偏差请直接纠正）
- 软件：ProcessPortViewer / 查看进程与监听端口，定位端口占用
- P0：进程列表、端口列表、按端口/PID/进程名搜索、结束进程
- P1：点击端口定位进程、右键复制 PID/路径
- 系统能力：枚举进程与端口；结束进程需管理员权限，失败要提示
- 交付：源码 + Release x64 绿色包
- 覆盖或不做的：覆盖 L4.3（关闭即退出，不做托盘）；不联网；不做开机自启
- 假设：默认 2 秒刷新；导出 CSV 暂不做
- 待确认：无
```

没有阻塞性问题，于是继续输出实现计划并开始写代码，不需要额外等一句"确认"。

## 第 3 轮：用户补充需求

```text
再加一个导出 CSV 的功能，其他不变。
```

AI 的处理：更新摘要，说明变更点和版本影响，再按增量修改。

```text
需求变更（已并入）
- 新增 P2：导出当前列表为 CSV
- 影响：UI 增加菜单项；新增对应测试；已交付 1.0.0 后新增功能，版本按 L1.1 从 1.0.0 → 1.1.0
- 其余需求与覆盖项不变
```

## 第 4 轮：用户改变覆盖项

```text
还是加托盘吧，关闭时最小化到托盘。
```

AI 的处理：以最新表述为准，撤销之前的覆盖，并说明影响。

```text
需求变更（已并入）
- 撤销覆盖：L4.3 恢复默认行为（关闭进托盘）
- 影响：恢复托盘菜单与"关闭到托盘"逻辑；版本 1.1.0 → 1.2.0
- 其余需求不变
```

## 另一种情况：需求不足

用户只说了目标，没说关键细节：

```text
做个文件整理工具。
```

AI 的处理：不猜核心规则，最多问 3 个会改变实现的问题，然后停下。

```text
需求理解（信息不足）
- 软件：文件整理工具 / 按规则整理本地文件
- 待确认（3 个）：
  1. 按什么规则整理：文件类型、修改日期，还是大小？
  2. 只处理选中的文件夹，还是扫描整个磁盘？
  3. 移动还是复制？是否需要预览和撤销？
```

用户回答后，AI 再补全需求理解并开始实现。

## 这个例子说明什么

- 用户不需要改模板，也不需要填 `V0 ~ V2` 表格。
- AI 必须先把自然语言整理成需求摘要，再动手。
- 后续补充、撤销覆盖都按"最新明确表述"处理，并说明版本影响。
- 没有阻塞问题时直接开始，不为了一句"确认"空转一轮。
- 用户说"其他不变"时，已有需求继续有效，不能被新需求覆盖掉。
